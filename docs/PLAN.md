# План реализации прототипа «О!дин запрос»

Источник требований: [TRACK.md](TRACK.md) (кейс трека) и [TZ.md](TZ.md) (ТЗ на MVP). Здесь — как мы их закрываем: решения по открытым вопросам, разбивка по четырём ролям и статус по этапам.

## Решения по открытым вопросам ТЗ

| Вопрос | Решение в прототипе | Почему |
|---|---|---|
| Какую LLM берём, есть ли бюджет | **Агент работает без LLM**: разбор запроса, правок и «что-нибудь ещё?» — детерминированный парсер русского языка; объяснения и озвучка — шаблоны по данным. Если задан `ANTHROPIC_API_KEY` (или OpenAI-совместимый `LLM_BASE_URL` для YandexGPT/GigaChat), LLM дополняет разбор с таймаутом и откатом на правила | Незнакомый запрос жюри должен дойти до ролика < 10 с и не упасть без сети/ключа |
| LangGraph | Свой минимальный `StateGraph` (тот же API: `add_node`, `add_conditional_edges`, `compile().invoke()`), граф отдаётся в Mermaid на `GET /graph` | Ноль внешних зависимостей, граф повторяет BPMN и его видно в UI («Как думал агент») |
| Синтез речи | Web Speech API браузера (`speechSynthesis`, ru-RU) + субтитры. Текст озвучки генерирует бэк (≤ 50 слов) и кэширует по ключу «ролик + даты + гости» | Бесплатно и мгновенно; Silero/SpeechKit — замена одного модуля |
| Travelpayouts, Яндекс.Расписания | Travelpayouts включается по `TRAVELPAYOUTS_TOKEN` (калибровка мока по кэшу цен); расписание поездов — таблица из открытых данных, интеграция с API Яндекс.Расписаний не сделана; без ключей — детерминированный мок | Ключей нет; на демо честно говорим, что билеты — мок |
| Погода | Open-Meteo Archive API (те же даты год назад) с таймаутом 2 с, иначе климатические нормы из каталога | Реальные данные, но без зависимости от сети на демо |
| Фото отелей | Вымышленные отели с синтетическими данными; «ролики» — процедурные иллюстрации со слайдшоу-наездом, помечены в кадре «Демо-ролик: иллюстрация». Поддержан `video_url` для настоящих роликов | Не выдаём выдумку за реальные отели и не используем чужие фото без прав |
| База | SQLite через SQLAlchemy (сессии + события для метрик) | Хватает для хакатона, переключается на PostgreSQL строкой подключения |

## Роли и зоны

- [x] 20 тестовых запросов с эталоном разбора и скрытыми предпочтениями — `backend/tests/test_queries.json`
- [x] Метрики и скрипт прогона — `backend/tests/run_metrics.py`, `GET /metrics`
- [x] Сценарий демо и честный список моков — [DEMO.md](DEMO.md)

### Бэкенд
- [x] FastAPI + SQLite, договор API ровно по ТЗ, SSE для подборки и пакета
- [x] Инструменты: `search_hotels`, `get_hotel_price`, `search_flights`, `search_trains`, `search_transfer`, `get_weather`, `check_connections`, `book`
- [x] Моки цен (база × сезон × день недели), наличия, трансферов (расстояние × тариф)
- [x] Интеграции: Open-Meteo (реально), Travelpayouts (по ключу)
- [ ] API Яндекс.Расписаний (сейчас таблица расписаний вручную)
- [x] Раздача собранного фронта с того же порта, Dockerfile

### Агент / LLM
- [x] `parse_request`: hard-параметры, стартовые веса, `source`, флаг «известно всё», противоречия → уточняющий вопрос
- [x] Ранжирование `score = Σ w·f − 0.3·sim(skipped) + 0.4·novelty` с жёсткими фильтрами (бюджет +10%)
- [x] Правила свайпов (`+0.2·(f−0.5)` / `−0.1·(f−0.5)`), подборка каждые 3 лайка
- [x] `explain` (why / tradeoffs / risks + сравнение), `voiceover` (≤ 50 слов)
- [x] `apply_correction` / `anything_else`: дельта → список затронутых компонентов → пересчёт только их
- [x] Граф шагов (BPMN) + трассировка узлов в ответе

### Фронтенд
- [x] 6 экранов под 390–430 px: запрос, лента, подборка, доуточнение, оплата, готово
- [x] Лента: полноэкранный ролик, озвучка, субтитры, плашка цены, счётчик лайков, свайп и кнопки
- [x] Поле правки доступно на всех экранах после запроса
- [x] Подсветка выведенных значений, выбор рейса «дешевле / быстрее», «Что-нибудь ещё?» + «Пропустить»
- [x] Пометка «оплата демонстрационная», план по часам и ваучеры

## Вне MVP (по ТЗ) — следующие шаги

1. Telegram Mini App (фронт уже мобильный, нужна обёртка и `initData`).
2. Работа после покупки: ранний заезд, смена дат, трансфер к купленному отелю.
3. Память между сессиями (профиль весов по пользователю).
4. Настоящий TTS (Silero/SpeechKit) и ролики по реальным фото партнёров.
